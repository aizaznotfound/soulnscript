# Soul & Script

A creative collective for readers, writers, thinkers, painters, and artists of every kind — built as a fast, free, static website ready for Cloudflare Pages.

---

## What's inside

> **August 2026 update:** this started life as a student newspaper template ("The GKMC Times") and has been rebranded and restructured into Soul & Script, a hub for arts. Along the way, every page's CSS and JavaScript — which used to live in one big `css/style.css` and `js/main.js` — was split into small, single-purpose files (below) so any future edit only touches one short file instead of scrolling through a thousand-line one. Two new content types were added: **Events** and **Team members**. See "How the split files fit together" and "Content types" further down.

```
soul-and-script/
├── index.html            Homepage (front grid, Poetry/Philosophy strips, Reflections, Films & Talks, Gallery)
├── news.html              Writing listing (Poetry, Prose & Picture Stories, Philosophy, Session Recaps — filterable + search)
├── opinions.html          Reflections listing (reader opinion pieces)
├── videos.html            Films & Talks gallery (YouTube embeds)
├── photos.html             Gallery listing (photography, painting, sketching)
├── events.html            Active Events (competitions/prizes) + Session Recaps (open mic, book sessions, movie talks)
├── team.html               Team roster, grouped by Founders/Media/Promotion/Judges/Communication/Finance
├── article.html            Single piece / video / photo detail page (?slug=... or ?video=... or ?photo=...)
├── about.html             The Manifesto — who we are, what we believe
├── contact.html            Contact form + reach-us info (Instagram, WhatsApp, email, phone)
├── 404.html               Not-found page
├── css/                    Styling, split into focused files — see below
├── editor.html            TEAM-ONLY PUBLISHING TOOL — writing/video/gallery/team member forms, plus reviewing contributor submissions
├── contribute.html        Public sign-up / login for reader-contributors
├── write.html              Simplified writing tool for logged-in contributors — submits for review
├── functions/api/          Cloudflare Pages Functions (login, publish, delete, register, contributor-login, submit, my-submissions, pending, review)
├── functions/_lib/         Shared server-side helpers (password hashing, sessions, GitHub API)
├── content/posts/          One JSON file per piece of writing — this is what you upload to publish
├── content/videos/         One JSON file per video
├── content/photos/         One JSON file per gallery piece
├── content/team/           One JSON file per team member (name, role, team, bio, photo)
├── build-content.js       Combines everything in content/ into js/content.js automatically
├── js/content.js           AUTO-GENERATED — never edit this by hand, see below

├── js/lib/                Small standalone helpers (formatting, sanitizing, data lookups)
├── js/render/              Card/hero/article/share-bar HTML templates — shared by every page
├── js/nav.js               Nav highlighting + mobile burger/mega-menu behavior
├── js/richtext.js          Shared Bold/Italic/Link editor toolbar (write.html + editor.html)
├── js/bootstrap.js         Boots up the shared behaviors on every page — loaded last of the shared files
└── js/pages/               One small file per page for that page's own logic (index.js, editor.js, write.js, ...)
```

### How the split files fit together

**CSS** — every page's `<head>` links `css/base.css` → `css/components.css` → `css/misc.css` (in that order, on every page), plus whichever of these a page actually needs:
- `css/editor-tool.css` — editor.html only
- `css/contributor.css` — contribute.html, write.html, editor.html, index.html
- `css/write-tool.css` — write.html, editor.html

Design tokens (colors, fonts, spacing) still live in one place — the `:root` block at the top of `css/base.css`.

**JavaScript** — every page loads, in this order: `js/content.js` (the data), then `js/lib/*.js`, then `js/render/*.js`, then `js/nav.js`, `js/richtext.js`, `js/bootstrap.js` (all shared, identical list on every page), then finally its own `js/pages/<page>.js` if it has one. This replaces the old single `js/main.js` — the code itself didn't change, it's just organized into short, single-purpose files now. `js/content.js` is still auto-generated by `build-content.js` and should still never be hand-edited.

### Content types

Four kinds of content, each its own folder in `content/`, each built by `build-content.js` into `js/content.js`:

| Folder | Shows up on | Categories? |
|---|---|---|
| `content/posts/` | news.html (Writing) or opinions.html (Reflections), depending on `category` | `news`, `campus`, `academics`, `events`, `opinion` — labeled Prose & Picture Stories / Poetry / Philosophy & Reflections / Session Recaps / Reader Reflections in the UI (see `CATEGORY_LABELS` in `js/lib/format.js`) |
| `content/videos/` | videos.html (Films & Talks) | — |
| `content/photos/` | photos.html (Gallery) | — |
| `content/team/` | team.html, grouped by the `team` field | `founders`, `media`, `promotion`, `judges`, `communication`, `finance` |

All four are published the same way — through `editor.html`'s tabs (Writing / Video / Gallery Piece / Team Member) — either with one-click Publish (writes straight to GitHub) or Download File Instead (manual upload). See the walkthrough below.

## Publishing content — the easy way (one small file at a time)

This is the part that matters most: **you never touch old pieces again.** Every piece of writing, video, gallery item, and team member lives as its own tiny file. To publish something new, you create and upload exactly one new file — nothing else.

Open **`editor.html`** in your browser (locally, or at `yoursite.pages.dev/editor.html` once deployed). It's a staff-only tool, not linked in the main reader navigation (there's a discreet "Staff: Content Editor" link in the footer).

1. Choose **Article / Opinion / News** or **Video** at the top.
2. Fill in the form — you'll see a live preview of exactly how it will look on the site as you type.
3. Click **⬇ Download This Article** (or **This Video**). This saves one small file to your computer, named after your headline, e.g. `research-symposium-2026.json`. Nothing on your live site changes yet.
4. On **github.com**, open your repository → click into the `content/posts` folder (or `content/videos` for a video) → **Add file → Upload files** → drag in the one file you just downloaded → scroll down and click **Commit changes** directly to the `main` branch.
5. That's it. Cloudflare Pages notices the new commit and rebuilds automatically, usually within a minute — your article goes live and appears in the right category, in search, and in "Most Read," with no other file touched.

**Editing or removing something already published:** open its file inside `content/posts` (or `content/videos`) on GitHub, click the pencil (✎) icon to edit the text directly in the browser, or the trash icon to delete it, then commit. Cloudflare rebuilds automatically either way.

Nothing in the Editor tool touches your live site directly — it only generates the one file for you to upload, so there's no risk of breaking anything and no login/database needed.

### Why this works without you managing a database

A small script called `build-content.js` runs automatically every time Cloudflare Pages builds your site. It reads every file inside `content/posts/` and `content/videos/`, and combines them into `js/content.js` — the file the website actually displays. You never open or edit `js/content.js` yourself; it's regenerated fresh on every deploy. This does mean you must set the **Build command** correctly in Cloudflare Pages (one-time setup) — see the Deployment section below.

### Editing content by hand (advanced / optional)

You never *need* to touch JSON directly — but each file in `content/posts/` is a plain, human-readable object with fields like `slug`, `title`, `deck`, `author`, `date`, `image`, `tags`, and `body` (an array of paragraphs). You can create or edit these directly on GitHub if you prefer, instead of using `editor.html`.

## How to publish a new article, story, or opinion piece manually (advanced)

You never need `editor.html` to publish — you can create the file yourself.

1. Inside `content/posts/`, create a new file named after your story, e.g. `convocation-2026-recap.json`.
2. Fill it in with this shape:
   ```json
   {
     "slug": "convocation-2026-recap",
     "category": "campus",
     "featured": false,
     "title": "Headline Goes Here",
     "deck": "A one or two sentence subheading.",
     "author": "Your Name",
     "date": "2026-08-01",
     "readTime": "3 min read",
     "image": "https://...",
     "imageCaption": "",
     "tags": ["Campus Life", "Ceremony"],
     "body": ["First paragraph...", "Second paragraph..."]
   }
   ```
   - `slug` — a unique, URL-safe id (no spaces), and it must match the filename.
   - `category` — one of `"news"`, `"campus"`, `"academics"`, `"events"`, `"opinion"`.
   - `featured` — set `true` if it should be eligible for the homepage lead story.
   - `body` — an array of strings, one per paragraph. The first paragraph automatically gets a decorative drop-cap.
3. Upload that one file to `content/posts/` on GitHub and commit — Cloudflare Pages rebuilds `js/content.js` automatically, usually within a minute.

Your new post will automatically appear in the right category listing, in search, and in "Most Read"/homepage rotation — no other file needs editing.

### Publishing a video

Create a new file inside `content/videos/`, e.g. `convocation-2026-highlights.json`:

```json
{
  "slug": "unique-id-no-spaces",
  "title": "Video Title",
  "deck": "One or two sentence description.",
  "author": "Soul & Script Media Team",
  "date": "2026-08-01",
  "youtubeId": "XXXXXXXXXXX",
  "thumbnail": "https://img.youtube.com/vi/XXXXXXXXXXX/maxresdefault.jpg"
}
```

`youtubeId` is the part after `watch?v=` in the YouTube URL. Tip: YouTube auto-generates a thumbnail at `https://img.youtube.com/vi/<youtubeId>/maxresdefault.jpg` — you can use that directly instead of hunting for a custom image.

### Adding your own photos

The starter sample uses a free placeholder photo from `picsum.photos` so the design has something to show. To use real photos:

- **Easiest:** upload images to an `images/` folder in this same repo and reference them as `images/your-photo.jpg` in the article's `image` field.
- Keep photos under ~500KB each for fast loading (Cloudflare's free tier has no bandwidth limit, but readers on mobile data will thank you).
- Recommended size: 1200px wide for lead/article images.

## Deploying for free on Cloudflare Pages

**Step 1 — Put this folder on GitHub**
1. Create a new (public or private) GitHub repository, e.g. `gkmc-times`.
2. Upload every file in this folder to that repo (drag-and-drop on github.com works fine, or use `git push` if you're comfortable with Git).

**Step 2 — Connect Cloudflare Pages**
1. Go to the Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Authorize GitHub and select your `gkmc-times` repository.
3. Build settings — **this is the one setting you must get right**:
   - **Framework preset:** None
   - **Build command:** `node build-content.js`
   - **Build output directory:** `/`
4. Click **Save and Deploy**. Your site will be live in under a minute at a URL like `gkmc-times.pages.dev`.

If you forget to set the Build command, the site will still work, but new articles you upload won't appear until you fix this setting under your Pages project → **Settings → Builds & deployments** and trigger a new deploy.

**Step 2b — Environment variables and KV namespaces (needed for `editor.html` and `contribute.html`/`write.html`)**
Under your Pages project → **Settings**:
- **Environment variables**: `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `GH_TOKEN`, `GH_OWNER`, `GH_REPO`, `GH_BRANCH`, and `SESSION_SECRET` (a long random string).
- **Functions → KV namespace bindings**: create and bind two namespaces — `CONTRIBUTORS` and `SUBMISSIONS` (see "Reader contributions" below for what each stores).

**Step 3 — (Optional) custom domain**
If Soul & Script owns a domain, add it under your Pages project → **Custom domains**. Cloudflare issues a free SSL certificate automatically.

**Step 4 — Publishing after launch**
Every time you upload one new file to `content/posts/` (or `content/videos/`) and commit on GitHub, Cloudflare Pages automatically reruns `build-content.js` and redeploys — that's the entire "CMS" workflow. No server, database, or login system required, and it costs nothing on Cloudflare's free tier.

## Reader contributions — accounts, a simple writing tool, and editor approval

Anyone can create a free account at `contribute.html` ("Write for Us" in the footer) with a username, email, WhatsApp number, and a password of their choosing — no admin has to create the account for them. Once logged in, they land on `write.html`: a simplified, distraction-free writing tool where they add paragraphs, headings, and images as separate blocks (no HTML/Markdown knowledge needed) and click **Submit for Review**.

**Formatting text** works the same way it does in a normal messaging app, not with markdown symbols: select any text and a small toolbar pops up above it (or use the Bold/Italic/Link buttons docked at the bottom, or Ctrl/Cmd+B, Ctrl/Cmd+I, Ctrl/Cmd+K). The staff editor's Story Body field has the exact same toolbar, so both tools work identically. Only bold, italic, and links are allowed through — anything else pasted in (say, from Word or Google Docs) gets cleaned up automatically, both in the browser and again on the server when a submission is approved.

Submitted articles are **not** published automatically. They sit in a review queue that only shows up for you, inside `editor.html`, under **📝 Contributor Submissions** (log in with your staff username/password as usual). From there you can:
- **✅ Approve & Publish** — writes the article to `content/posts/` exactly like the staff editor does, live within a minute.
- **✕ Decline** — with an optional note, which the contributor can see next to that submission on their own `write.html` page.

Contributors never get GitHub access, staff credentials, or the full editor — just the simplified block-by-block writer and a view of their own submission statuses.

### One-time setup this feature needs

In addition to the environment variables already described below, this feature needs:

1. **Two Cloudflare KV namespaces** — Cloudflare dashboard → your Pages project → **Settings → Functions → KV namespace bindings** → add:
   - Variable name `CONTRIBUTORS`, bound to a new KV namespace (e.g. `gkmc-contributors`) — stores contributor accounts (hashed passwords only, never plain text).
   - Variable name `SUBMISSIONS`, bound to a new KV namespace (e.g. `gkmc-submissions`) — stores pending/approved/rejected article drafts.
2. **One more environment variable**, alongside `ADMIN_USERNAME` etc.: `SESSION_SECRET` — any long random string (e.g. generate one with `openssl rand -hex 32`). It's used to sign contributor login sessions; it isn't a password anyone types in.

Nothing else changes — the same `GH_TOKEN` used for staff publishing is reused when you approve a contributor's submission.

## Customizing the design

All design tokens (colors, fonts, spacing) live at the top of `css/base.css` under `:root`. Key variables:

- `--maroon` — primary accent color (Soul & Script brand color)
- `--paper` — background color
- `--display` — headline font (Fraunces)
- `--body` — article body font (PT Serif)
- `--utility` — nav/meta/label font (Barlow Condensed)

Change these once and the whole site updates consistently.
